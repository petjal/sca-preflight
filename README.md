# SCA Preflight: A Safe Test Project for Checking Your SCA Scanner

**SCA Preflight** is a synthetic, polyglot test project tree for checking whether your Software Composition Analysis (SCA) scanner (Detect, Syft, Trivy, Snyk, etc.) is actually finding the hidden dependencies, known vulnerabilities, and license changes in your builds before you trust its results in production.

This public repo contains:
- **`benchmark/`**: The free test project capsule, ground-truth checklist, and a [plain-English walkthrough of the 8 file types inside the capsule](benchmark/README.md) so you can test your own scanner right now.
- **`examples/`**: Sample output reports generated by **`sca-ops-toolkit`**, a separate private Python toolkit built by Emil Walter "Pete" Jalajas for pre-scan checks, scanner tuning, and BOM cleanup.

---

## 1. What Problems Does This Catch?

In real-world monorepos and C/C++/Java/Go/Rust builds, SCA scans usually run into three problems:

1. **Default scanner settings miss nested files (Blind-Spot Traps)**:
   - Out-of-the-box Detect flags (`--detect.detector.search.depth=0`, `--detect.detector.search.continue=false`, `--detect.binary.scan.search.depth=0`, `--detect.blackduck.signature.scanner.individual.file.matching=NONE`) quietly skip nested subfolders, shaded uber-JARs, UTF-16 manifests, and stripped C/C++ `.so` libraries while still exiting `0` (`SUCCESS`).
2. **Silent open-source license changes (Rugpulls)**:
   - Package managers don't warn you when an upstream library switches from a permissive license (`Apache-2.0`, `BSD-3-Clause`, `MPL-2.0`, `LGPL`) to a restrictive or copyleft license (`AGPL-3.0`, `SSPL-1.0`, `RSALv2`, `BSL-1.1`, `GPL-3.0-only`).
3. **No record of what files or CLI flags produced the BOM**:
   - Standard `.bdio` and SBOM files list the components the scanner found, but don't record a hash of **which files were actually on disk** or **which CLI flags were used** when the scan ran.
   - `sca-prescan` solves this by computing a fast, multithreaded **3-layer folder & file fingerprint** (`sca-sig:v2:L0=<folders>:L1=<dep_files>:L2=<source_files>:CFG=<cli_flags>`) and stamping it into the Project Version Notes in the web UI:
     - **`L0` (Folder Layout)**: Instant hash of the folder tree, file counts, and byte totals without reading file contents.
     - **`L1` (Dependency Inputs)**: Hash of 100% of lockfiles, manifests, Dockerfiles, JARs, tarballs, and binaries on disk (if `L1` hasn't changed between commits, your dependency inputs haven't changed).
     - **`L2` (Source Files) + `CFG` (Scanner Flags)**: Top-down hash of the source code tree plus the exact Detect CLI flags used for the scan.

## 2. Quickstart: Unpack the Test Project & Run Your Scanner

[`benchmark/sca_preflight_reference_capsule.b64`](benchmark/sca_preflight_reference_capsule.b64) is a Base64-encoded `.tar.gz` archive (~11 KB across 25 files) containing synthetic manifests, tiny dummy JAR metadata stubs, and dummy C/C++ `.so` version headers. See [`benchmark/README.md`](benchmark/README.md) for a plain-English breakdown of all 25 files and 8 concrete examples of what is inside each file before unpacking. It contains **only synthetic metadata stubs** and **zero third-party copyleft source code**, and is Base64-encoded so GitHub Dependabot does not open automated alerts on the sample manifests in this repo.

Unpack it into `/dev/shm/` on Linux or macOS:

```bash
mkdir -p /dev/shm/sca_preflight_reference_scan && \
  grep -v '^#' benchmark/sca_preflight_reference_capsule.b64 | base64 -d | tar -xzf - -C /dev/shm/sca_preflight_reference_scan
```

Run your current SCA scanner against `/dev/shm/sca_preflight_reference_scan` and compare what your scanner finds against the checklist in [`benchmark/GROUND_TRUTH_MANIFEST.json`](benchmark/GROUND_TRUTH_MANIFEST.json):

- **21 Known CVEs Across 25 File Locations**:
  - Includes Log4Shell (`CVE-2021-44228` in both a regular JAR and shaded inside `telemetry_agent_shaded.jar`), Text4Shell (`CVE-2022-42889` in both regular and shaded JARs), Spring4Shell (`CVE-2022-22965`), Apache ActiveMQ (`CVE-2023-46604`), PostgreSQL JDBC (`CVE-2022-21724`), BouncyCastle (`CVE-2020-28052`), SnakeYAML (`CVE-2022-1471`), PyYAML (`CVE-2020-14343` in both a tarball and a UTF-16LE `requirements.txt`), OpenSSL `3.0.4` (`CVE-2022-2274`, `CVE-2022-3602`), zlib `1.2.11` (`CVE-2022-37434` in both `.tar.gz` and a stripped `.so`), curl `8.3.0` (`CVE-2023-38545`), libexpat `2.6.2` (`CVE-2024-45490`), lodash (`CVE-2021-23337`), cross-spawn (`CVE-2024-21538`), Newtonsoft.Json (`CVE-2024-21907`), urllib3 (`CVE-2023-45803`), cryptography (`CVE-2023-49083`), and Go modules (`CVE-2023-39325`, `CVE-2023-45288`, `CVE-2024-24786`).

## 3. Sample Output Reports in `examples/`

- **[`examples/LLM_INGESTION_REPORT.md`](examples/LLM_INGESTION_REPORT.md)** - **Pre-Scan Summary & AI Brief (`sca-prescan --ai-brief`)**:
  - A single Markdown report with workstation paths stripped out so you can paste it straight into your internal company AI (Copilot, Claude, ChatGPT Enterprise, Gemini).
  - Shows the `sca-sig:v2` workspace fingerprint, recommended Detect CLI flags, expected component counts (Section 3), CVE and license tables (Sections 4-5), and copy-paste AI prompts (Section 6).
- **[`examples/bom_ifttt_dry_run_preview.txt`](examples/bom_ifttt_dry_run_preview.txt)** - **Rule-Based BOM Cleanup Preview (`sca-bom-ifttt`)**:
  - Shows how [`examples/sample_bom_ifttt_rules.toml`](examples/sample_bom_ifttt_rules.toml) cleans up noisy BOMs via the REST API (defaults to safe `--dry-run` preview mode with audit comments):
    - **Phase 1 (Scan Cleanup)**: Unmapping old, stale CI build scans before touching components.
    - **Phase 2 (BOM Cleanup)**: Rolling noisy subcomponents (`jackson-core`, `jackson-annotations`) under their parent (`jackson-databind`), ignoring duplicate `N-1` signature-scan guesses when an exact package-manager match exists, flagging filename version mismatches, and resolving dual-license GPL entries.
    - **Zero-Day / Unindexed Component Check (`--verify-bdio`)**: Warning when a brand-new component version is in your `.bdio` upload but gets dropped from the server BOM because the KB hasn't indexed it yet.
- **[`benchmark/GROUND_TRUTH_MANIFEST.json`](benchmark/GROUND_TRUTH_MANIFEST.json)** - **Answer Key (JSON)**:
  - The full list of expected CVEs, license rules, blind-spot traps, and SHA-256 fingerprints for `/dev/shm/sca_preflight_reference_scan`.

## 4. What's in This Public Repo vs. the Separate Private Repo (`sca-ops-toolkit`)

- **In this public repo (`sca-preflight`)**:
  - Only the free test project (`benchmark/`) and sample output files (`examples/`). In this test project, you have [`benchmark/GROUND_TRUTH_MANIFEST.json`](benchmark/GROUND_TRUTH_MANIFEST.json) as an answer key to see what your scanner missed.
- **In a separate, private repo (`sca-ops-toolkit`)**:
  - In your own production builds, you don't have an answer key when a scan finishes with `0` errors but quietly skips a shaded uber-JAR, a stripped `.so` library, or a `UTF-16` manifest.
  - That is what **`sca-ops-toolkit`** (`sca-prescan`, `sca-bom-ifttt`, `sca-tealeaves`, `sca-log-sanitize`, `sca-mcp`) is built for:
    - **`sca-prescan` runs in seconds *before* your regular SCA scanner** to spot early hints of these critical issues while automatically generating the tuned CLI flags (`search.depth`, memory limits, safe folder exclusions, and `sca-sig:v2` fingerprint) so your main scanner catches them cleanly.
    - **Honest Scope (Small Hit-List, Zero Promises)**: `sca-prescan` is **not** a replacement for a full SCA vulnerability database and **promises nothing** when it comes to catching every CVE out there. Its built-in catalog is intentionally tiny - just a curated hit-list of well-known CVSS 9.8-10.0 / CISA-KEV disasters (Log4Shell, Spring4Shell, Text4Shell, OpenSSL, zlib, curl, pgjdbc) and major license rugpulls (`AGPL-3.0`, `SSPL-1.0`, `RSALv2`, `BSL-1.1`). Its job is to give you a fast, 5-second heads-up on the worst-of-the-worst blind spots and tune your main scanner so your real vulnerability database does its job properly.
    - **`sca-bom-ifttt` runs *after* your scan** to unmap stale CI build scans, roll up noisy subcomponents, suppress duplicate `N-1` signature-scan noise, and flag brand-new component versions dropped by the server KB.
  - The toolkit is written in plain, readable Python 3.11+ (using only the Python standard library, with no compiled binaries, no extra pip packages to install, and no background network calls) so your security team can easily read the code and run the InfoSec review prompts in Section 6.2 of [`examples/LLM_INGESTION_REPORT.md`](examples/LLM_INGESTION_REPORT.md).
- **Blind Public-Repo A/B Challenge & Feedback Intake (Optional PGP Encryption)**:
  - Any benchmark published by a tool author can be accused of "teaching to the test."
